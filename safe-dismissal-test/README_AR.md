## اعتماد الربط مع Render PostgreSQL
تحتاج خدمة الويب فقط إلى متغير البيئة `DATABASE_URL` الخاص بقاعدة `miral-safe-dismissal-test-only-2026`. يضاف **داخل لوحة Render** بواسطة صاحب الحساب، ولا يُنسخ إلى المحادثة أو المستودع أو JavaScript. لا تغيّر قاعدة «انصراف آمن» الأصلية.

1. افتح PostgreSQL test database في حساب Render/مساحة Student Results، واختر Connect ثم **Internal Database URL**.
2. افتح خدمة `miral-safe-dismissal-ops-test` ثم Environment واختر Add Environment Variable. الاسم `DATABASE_URL` والقيمة الرابط الداخلي الذي نسخته.
3. احفظ الإعدادات وأعد تشغيل الخدمة. `DEMO_ONLY=1` و`SEED_SECRET` تم حفظهما مسبقًا على خدمة الويب فقط، دون إدراجهما في المستودع.
4. تحقق من `/api/health`: يجب أن تظهر `databaseReady: true` و`productionEnabled: false`؛ وإذا لم تظهر، فلا تستخدم الموقع للاختبارات حتى يتم إصلاح الاتصال.

## مسار الاختبار
أرسل ولي الأمر رمز `DEMO-1012` → أكدي الحضور من الاستقبال → استدعاء ومغادرة المنطقة → الوصول إلى البوابة → إقرار تحقق الهوية والتفويض → اعتماد تسليم تجريبي فقط.

منع إقرار الهوية يتسبب في رفض التسليم برمز HTTP 409. تمنع قاعدة Postgres تكرار الطلب النشط للطالبة عبر فهرس فريد، وتعمل عمليات التحويل داخل Transaction بقفل الصف. لا يمكن لحساب الاستقبال اعتماد التسليم. كل الحالات وهمية، ولا يُرسل أي إشعار إلى أولياء الأمور الحقيقيين.

تُحدّث واجهات الموظفات بياناتها كل 3 ثوان في الظروف الطبيعية. هذا Polling خادمي وليس Broadcast لحظيًا مضمونًا. تختبر CI مراحل الصلاحيات وتكرار الطلبات ورفض تجاوز فحص الهوية باستخدام قاعدة Postgres منعزلة داخل GitHub Actions.
